Three structural facts worth knowing before writing a reader:

- The objects are **not parquet**. They are Databento DBN under zstd, so there is no parquet footer to read and `read_parquet` will not open them. Row counts and schema come from the DBN header plus a sampled decode instead.
- **ES is present**, with its own year of history, and the OPRA prefixes are QQQ options as described.
- **DBN version is not uniform inside `raw/`.** Most of the mirror is v1; the six corrected objects are v3. Both decode to the same columns and dtypes, but the version is recorded per object in `data/manifest.json` under `files` rather than assumed. This mix is permanent.

**The date in every filename is a UTC calendar day, not a CME session date.** Confirmed from each file's DBN metadata `start`/`end`, which sit on UTC midnight. The CME session runs 17:00 CT the previous evening to 16:00 CT, so a session's data is split across two consecutive files, and the bucket contains Sunday-dated files holding only the weekly 17:00 CT open up to UTC midnight. Any loader that treats one file as one session is wrong.

The sample deliberately covers all four shapes a UTC-day file takes:

- **midweek** — a full 24 UTC hours, i.e. 19:00 CT the previous day → 18:59 CT under CDT and 18:00 → 17:59 CT under CST. Contains the tail of one session (through the 15:00 CT equity close and 16:00 CT futures close), the 16:00–17:00 CT halt as an empty hour, and the *start of the next session* from 17:00 CT.
- **friday** — same window, but Globex shuts for the week at 16:00 CT and does not reopen, so there is no 17:00 CT hour. A missing evening here is correct, not a gap.
- **sunday** — only the 17:00 CT weekly open through the UTC midnight boundary: two hours under CDT, one under CST, giving a file two orders of magnitude smaller than a weekday's.

So: **full Globex, not RTH** — every session hour is present, including the overnight. But no file is a session. Bar building must concatenate consecutive files and cut on the 17:00 CT boundary; anchoring VWAP or session highs to a file boundary would anchor them to 18:00/19:00 CT, an hour or two into the session, and would shift by an hour at each DST change.

## 9. Corrections and divergence from the source lake

**`raw/` deliberately diverges from `gexalgo/raw` on 6 objects and on nothing else.**

Task 1 found six objects under `raw/trades/NQ/` whose DBN header reported `ES.FUT`, holding data byte-identical to the `raw/trades/ES/` object of the same date; NQ had no data at all on those dates. Correct NQ data was re-downloaded from Databento and, on 2026-09-08, in-place overwrite; the patches/ prefix that held the replacements was purged. The contaminated originals remain in `gexalgo/raw`, so nothing is unrecoverable.

`config/corrections.yaml` is the record of that. It is evidence, not a mechanism: nothing reads it at runtime, no path is resolved anywhere, and each key below is simply the canonical object for its (symbol, date).
